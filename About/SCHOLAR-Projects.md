# SCHOLAR Projects

The SCHOLAR (Student-Crafted Hub for Open Learning and Academic Resources) projects are a core component of this course. These activities develop technical skills, communication, and collaborative workflows through shared, team-based contributions.

---

## Why SCHOLAR Matters

A central goal of this course is learning **how to learn independently**.

Technology is constantly evolving, and in real-world data science work you will regularly need to learn new tools and methods outside of formal instruction. SCHOLAR projects are designed to simulate this process.

Students are expected to:

- identify something they do not yet know  
- learn it independently  
- apply it in context  
- explain it clearly to others  

By contributing tutorials to a shared repository, teams create resources that allow future students to start ahead rather than repeat the same learning process.

---

## Core Idea

> **Learn something new and teach it to the next group.**

Teams develop tutorials on topics **not already in the repository**, with future students as the intended audience. These tutorials become part of a growing shared resource.

---

## Learning Goals

SCHOLAR projects help students:

- learn new tools and techniques independently  
- communicate technical ideas clearly  
- collaborate using shared workflows  
- contribute to reusable learning resources  

---

## Learning and Practicing Git

SCHOLAR work takes place in a shared Git repository, where multiple teams contribute simultaneously.

Students gain experience with:

- contributing to a common codebase  
- coordinating work with others  
- using issues and pull requests  
- managing revisions and conflicts  

This provides a realistic collaborative environment and reinforces that version control is part of working with others—not just an individual tool.

---

## Project Structure

SCHOLAR activities follow a staged progression:

1. **Familiarization** – clone and explore the repository  
2. **Contribution Practice** – submit issues and pull requests  
3. **Topic Selection** – identify a new tutorial area  
4. **Development** – create a complete tutorial  
5. **Review** – give and respond to feedback  
6. **Contribution** – submit a polished final resource  

The schedule reflects this progression through activities such as pull request practice, topic selection, and deep tutorial review.

## Honors Option (Documentation Management Team)

Students in the Honors College may complete an Honors Option by participating in the **Documentation Management Team**, which helps support and maintain the SCHOLAR repository.

Students interested in this option must complete the Honors College application form. As part of this form, you will be asked to provide a description of the experience and expected deliverables.

**Please copy and paste the following text into your submission:**

> Student's taking the honor's option will join the Documentation Management team. Members of the Documentation Management team will be added to a special Microsoft Team Channel and will be expected to coordinate with each other (and the instructors) to divide the required work needed to manage the "SCHOLAR" (Student-Crafted Hub for Open Learning and Academic Resources) git repository. This includes organizing the issues list, reviewing pull requests, adding new features to the repository and helping other members of the course with git related questions. This role doesn't require that you are currently a git expert however in your duties on the management team you will be learning a lot about git. 
> 
> To get credit for the Honor's Option students must receive an overall class grade of 3.0 or higher, contribute to the documentation management team and email a short (less than 1-page) report to the instructors before the last day of class describing what they learned being on the management team and a list of tasks/responsibilities that they were responsible for managing. 


After submitting the Honors form, students should also email the instructors to indicate their interest in joining the Documentation Management Team.

## Why This Matters

SCHOLAR projects are designed to reflect real-world practice:

- learning new skills independently  
- working in shared codebases  
- communicating clearly  
- contributing knowledge others can build on  

These are essential skills for working in modern data science environments.
